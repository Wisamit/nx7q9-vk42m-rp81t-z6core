## Problem
Stage 54 accepted an independent clinical/financial expert's disposition only after a full current-grant, source/live HMAC verification. However its bilingual queue allowed a reviewer to click a decision immediately, possibly encountering a denied stale, superseded or already-decisioned referral without upfront explanation. Stage 55 added author-side review lifecycles; a safe, read-only expert-side **preflight** is needed. Concurrently, the first post-merge Stage 55 CI #978 attempt 1 failed on a MariaDB `ER_LOCK_DEADLOCK` in the pre-existing Stage 45 *test fixture*, line 117. Stage 55 tests themselves succeeded; CI #978 attempt 2 later passed at the identical SHA.

## Implementation
- `GET /api/catalog/imports/[id]/bundle-drift?reviewFlagId=<UUID>`: read-only review-preflight mode. Requires a single valid UUID and rejects other query parameters. It uses the **exact existing Stage 54 expert-authorization transaction**: tenant lock, RepeatableRead, active original/session and persisted roles, separate medical/financial grants, full-batch branch/department/parent scope, latest Stage 53 triage evidence, fresh HMAC of exact source/live clinical/price values and prior Stage 54 decision lookup. A reviewer who authored or flagged the same file fails closed. `EXPERT_REVIEW_READY` only means an eligible pending *finding*, **not** medical or financial approval.
- Preflight executes **no audit writes** and never returns raw values or import rows, prices, critical thresholds, reference ranges or patient data. Returns the class, non-sensitive row number, signed-source indication, and `approved:false, activated:false, liveWrites:false`. Stale or revoked requests remain denied; invalid/multiple query fields are rejected.
- The bilingual independent-expert queue requires the reviewer to click **Verify current evidence / فحص الدليل الحالي** before either procedural decision button is enabled. UI distinguishes READY, STALE and CONFLICT without displaying sensitive content. Every subsequent PUT independently redoes **all authorization and evidence checks**, preventing a time-of-check/time-of-use bypass. The preflight is an extra guard, not a replacement.
- A conflicting attempted disposition against an already decided Stage 54 flag now returns `409 expert_decision_conflict`, rather than returning `EXPERT_DECISION_ALREADY_RECORDED` misleadingly for the opposite choice. An exact same-choice retry stays idempotent; invalid historical decision data fails closed.
- `tests/stage-45-legacy-unit-preparation-mariadb.integration.test.ts`: the competing transaction now starts **after** the first writer performs all FK-referencing unit creation/test claim writes and **before** its COMMIT. This retains the two-connection organization lock and second writer replay tests while avoiding a test-only circular FK lock order. No LIS clinical or billing production code changed for this CI stability fix.

## Explicit non-goals
- `EXPERT_REVIEW_READY` is **not** a clinical director's approved reference interval, posted price activation, cash settlement authorization, electronic signature or signed source configuration publish permission. `CONFIRM_FINDING` remains procedural triage only. No catalog master, clinical result, billing invoice, effective-date data or patient identity history can be amended by this path.
- There is **no database migration**, no new operational approval authority and no scope removal. Final medical/financial signing policy, release conflict rules, branch-specific signatories, key rotation and deploy-side disaster recovery remain future work.
- Manual, hardware/analyzer/barcode, cashier/clinical/finance UAT and disaster recovery remain **DEFERRED**, not falsely marked passed.
