# Stage 133 — Native Excel XLSX Review-Only Catalog Configuration (Software)

**Base SHA:** Stage 132 preparation merged and owner confirmed deployed `2a52fc9f2d5335a7408eb733d11db05ca03b8c04`. **Master Scope §87:** controlled CSV/Excel import/export for test catalog, components, intervals, prices, units, mappings and selected configuration; validation and audit. **Current status:** partial software closure: supported review-only XLSX paths; full entity-by-entity Excel import and activation parity still require separate engineering and qualified approvals.

## Added without schema migration or business-rule relaxation

- **Read-only XLSX export** via existing catalog export component: choose exactly one type among TEST, COMPONENT, UNIT, PANEL, PACKAGE, REFERENCE_INTERVAL, PRICE_LIST, PRICE_LIST_ITEM or PRICE_LIST_PACKAGE_ITEM. Uses the same server authorization, tenant-scoped paged export, branch/department visibility rules and audit event as the pre-existing CSV review export. Workbook is produced in the browser and has **one worksheet**, never external scripts/links/macros or executable Excel formulas. UTF-8 Arabic strings and DECIMAL/ISO dates remain literal text to avoid lossy Excel coercion. The original selected scoped JSON bundle remains the authoritative structured format.
- **XLSX review template upload** for COMPONENT, PRICE_LIST_ITEM and REFERENCE_INTERVAL through existing `/api/catalog/imports/csv` endpoint (also still accepts CSV). The converter reads native ZIP/SpreadsheetML with bounded decompression, UTF-8 XML checks, CRC checks, no external resources/macros, strictly one visible sheet, no formulas or merged cells, fixed 24-column maximum, no binary/Excel expression execution. Imported cell values are emitted as exact quoted CSV text and fed into **unchanged clinical/financial CSV review parser and validators**.
- Real XLSX upload is source-checksummed using **original file bytes**. Server keeps `sourceType: CSV_REVIEW`, `status: DRAFT`, `validatedAt: null`, `reviewOnly: true` and adds `uploadedFormat: XLSX` plus a separate `CATALOG_XLSX_REVIEW_STAGED` audit action. This intentionally preserves existing revalidation/commit prohibitions for review-only batches. **No clinical range, component, price, method or test is activated.**
- XLSX templates download directly alongside CSV templates. Import requires original review-template headers; **paged configuration XLSX export is human-review evidence, NOT a round-trip import file**. HTML/javascript hyperlinks and formulas are not exported as executable cells; formulas in uploaded workbook cells cause rejection.
- Server upload limit **2 MiB compressed** with byte-stream bounding; ~5 MiB per decompressed entry/12 MiB cumulative, 100 ZIP entry cap and no CSV rows above 20,000. Reader supports ZIP STORE/DEFLATE, Excel inline/shared string and literal numeric cells; does not interpret Excel style-derived date formats. Numeric date serials therefore fail downstream effective-date validation rather than being guessed.
- Existing `pricing.manage`, `catalog.reference_ranges.manage`, active branch and active clinical import scope restrictions are reused; **no bypass route**. The import template is limited to three review-only entity classes because the pre-existing clinical/financial master-activation workflow does not accept generic workbook writes.

## Explicit non-claims / remaining §87 work

1. This stage **does not complete the entire Master Scope §87**. Existing broad export is extended to XLSX *review*. Native Excel imports of entire test/unit/panel/package/configuration bundles, reference/method/analyzer mapping activation, and full Excel import/export field round-trip parity are **not implemented** in this stage. Those must not be silently marked done.
2. An XLSX file and its decoded worksheet are **untrusted**, never a substitute for the cryptographically attested JSON atomic bundle, a clinical range review, a financial price authorization or a DB restore. No script can declare §87 real-world UAT PASS.
3. The prepared Stage 132 private UAT register remains `NOT_EXECUTED`. Other unresolved §75 analyzer specimen-interference policy, §86 jurisdictional tax and §88 legacy MDB row reconciliation remain OPEN. No actual analyzer hardware, operator signoff, restore drill or consent verification is claimed here.
4. No application privileges are expanded. No new DB migrations, no new credentials/deployment infrastructure, no changes to historical clinical or financial snapshots. Hostinger owner deploy only after independent main SHA CI and backup review.
