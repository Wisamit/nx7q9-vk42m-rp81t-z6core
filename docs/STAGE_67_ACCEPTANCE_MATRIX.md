# Stage 67 — Dual-Audit Review Queue Watermark (Drafts and Independent Reviews)

## Objective
Close the Stage 66 cursor consistency gap: an independent reviewer can record a procedural decision between pages without changing the latest *draft* event; a newer event with a backdated timestamp or a lower UUID inside the same millisecond may not change the currently highest-sorted audit event. Navigation must then fail closed, rather than implying that eligibility has stayed unchanged.

## Implementation
- `src/lib/catalog-policy-queue-signed-cursor.ts`: cursor format **v3**, retaining domain-separated HMAC-SHA256, current user/organization/branch binding, 20-minute maximum TTL and canonical strict validation. In addition to draft head, the signed cursor records the count of draft events and a second **independent-review** watermark `{latest,count}`. Strictly reject malformed count/head pairs, noninteger/negative counts and old v2/legacy tokens. A scope change or invalid signature still fails closed.
- `src/app/api/catalog/imports/policy-review-queue/route.ts`: within the existing organization `FOR UPDATE`, `RepeatableRead` transaction and after live original/session branch/department checks, query the current draft and independent-review latest AuditEvents **and their counts**. Reuse these for the whole cursor chain. A review decision, even on an unrelated current-branch draft, or any new draft event invalidates the continuation with HTTP 409. The draft count catches hidden same-millisecond lower-UUID and backdated additions, while the review count also catches older-sort procedural reviews. No actor identity, raw audit data, comment contents or clinical/financial values are returned.
- `src/components/catalog-policy-draft-review-queue.tsx`: 409 clears stale pages and displays an AR/EN message that **drafts or reviewer decisions** have changed; validates the longer signed token within a 768-character cap.
- `tests/stage-67-policy-queue-dual-audit-watermark.test.ts`: v3 signing, zero/nonzero review watermarks, same-millisecond/backdated appends, scope isolation, tampering, expiry, stage-specific server checks and no live-master writes. Stage 66 tests updated for v3 while retaining their independent scope/expiry/transaction coverage.
- `tests/stage-67-policy-queue-dual-audit-watermark-mariadb.integration.test.ts`: two independent SQL connections, real author plus distinct clinical/financial procedural reviews, a deliberately backdated review, lower-UUID equal-millisecond draft event and foreign-tenant/no-master-write checks.
- `.github/workflows/ci.yml`: dedicated Stage 67 MariaDB gate; earlier suites retained.

## Safety and constraints
- Same tenant, branch and reviewer: the HMAC cursor is **navigation state, not permission**, and independent review GET/POST continue to enforce current permissions, complete up-to-1,000-revision history and full staged 5,000-record live master scope before exposing choices or logging decisions.
- Count + latest detects appended or removed events, but it does not authenticate AuditEvent data or detect a privileged direct-database mutation that preserves both the count and latest record. Production database role isolation, backup/audit retention and non-destructive clinical history remain mandatory.
- On Stage 67 release, Stage 66 v2 cursors deliberately expire; refresh starts the new signed cursor chain without DB migration.
- The count queries read scoped audit entries for the active organization/branch/action. These are read-only integrity checks, not exhaustive cross-request snapshots of clinical masters. Changes in roles, department scope or source-data integrity are still independently revalidated on every page and detail operation.
- `approved=false`, `signingEnabled=false`, `activated=false`, `liveWrites=false`; drafts and procedural reviews are **not signed or approved**. No catalog master activation, invoice or price publication, report amendment, patient history overwrite or database schema migration.
- Human clinical/financial authority appointment, MFA reauthentication and effective-dated live application remain deferred until explicit owner governance decisions. Full UAT and Hostinger release confirmation remain separately gated.
