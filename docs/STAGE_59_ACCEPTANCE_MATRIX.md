# Stage 59 — Draft-Only Clinical/Financial Signatory Policy Ledger

## Baseline
Stage 58 merge `1c4194c06231333356d1d11209213cd189c4d8cb` independently passed CI #988. Owner explicitly confirmed successful Hostinger deployment. Repository is intentionally PUBLIC. Analyzer Bridge PR #128 remains separate DRAFT/unmerged. All 88 sections of `02_MASTER_SCOPE.md` remain required.

## Why only drafts
A laboratory needs defined authority for clinical intervals/critical limits, financial price publication, branch delegation, maker-checker separation, fresh signer authentication, and immutable versioned publication. The project has not yet decided or legally/clinically approved those exact governance rules. Existing catalog/medical-range/pricing **manage** permissions are not final signer permissions. Implementing an active clinical/price approval button now would be unsafe. Stage 59 therefore adds an append-only **unsigned policy proposal ledger** that cannot activate a price, range, result or report.

## Delivered
- `src/lib/catalog-signatory-policy-draft.ts`: strictly allowed seven proposal topic enums, all defaulting to `UNDECIDED`: medical authority, financial authority, branch coverage, distinct maker-checker, MFA-at-signing proposal, future effective-dated immutable versioning, and clinical critical-range review. Every proposal is explicitly **nonbinding** and may be incomplete. No role, identity or policy is auto-granted.
- Source-, branch-, batch-, tenant-, and content-bound SHA-256 **integrity digest**; NOT an electronic signature or tamper-proof authenticated signature. Historical ledger entries are validated fail-closed for identifier context, draft-only state, version, digest and mandatory false approval/activation flags.
- `POST /api/catalog/imports/[id]/bundle-drift?policyDraft=1`: strict JSON <=2KiB, exactly `expectedRevision` and `proposal` fields, allowlisted proposal fields and values, only same-origin browser submission; uses the **same complete 5,000-row author-scoped clinical/finance/reference/price and branch+department permission revalidation** and tenant `FOR UPDATE` RepeatableRead lock as Stage 57 governance report, not a shadow authorization path. Per-batch/branch/author history is append-only via `CATALOG_BUNDLE_SIGNATORY_POLICY_DRAFT_RECORDED` AuditEvent; optimistic revision conflict 409; identical submissions are idempotent; corrupt history fails closed. No master writes, no database migration. Source checksum stays unchanged; changing the underlying clinical/financial values never grants approval. Unset decisions are allowed in draft only.
- Existing `GET ...?governance=1` returns **only latest owner-scoped, branch-scoped proposal, revision and digest**; server keeps person/org IDs and source checksum in Audit and never exposes them through the new policy draft annex. Each whole-bundle inspection logs a count-only governance audit entry with draft revision/state.
- Bilingual `CatalogPolicyDraftEditor` integrated into Stage 57 governance UI. Clearly labelled "Draft only / مسودة غير ملزمة", topic-by-topic choices in Arabic and English and unresolved-topic count. "Record nonbinding draft in Audit" explicitly does not sign, approve or activate any configuration. Displays conflict/errors and reloads latest revision after successful append.
- Hard flags `UNAPPROVED_DRAFT`, `reviewOnly:true`, `approved:false`, `signingEnabled:false`, `activated:false`, `liveWrites:false` in every version, AND Stage 57 blanket clinical and financial application gates remain false.

## Explicitly not implemented
This ledger is **NOT the organization's approved policy**, not an authenticated electronic signature, not a clinical validation workflow, not a financial approval engine, not delegation/assignment of signer roles, and not a versioned application path. Proposed choices require explicit stakeholder review and approval, signature method/legal assessment, clinical safety acceptance, key/credential management, branch-scoped signer appointment, backup/restore and end-to-end hardware/clinical/financial UAT before production release. The current final application gates remain **permanently blocked in this stage**, even if every topic is selected.

Full 88-section LIS scope remains. Manual analyzer/barcode, clinical/finance UAT and disaster recovery are deferred (never falsely passed). The public repository, patient privacy and unmerged Analyzer Bridge Draft #128 remain unchanged.
