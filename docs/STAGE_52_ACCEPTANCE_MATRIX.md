# Stage 52 — Full-Batch Live Catalog Drift Review

**Baseline:** Stage 51 merged main `c4a807a4cb08a6e51db1ad84e8285b3c4312906f`, main CI #968 SUCCESS; Hostinger deployment independently confirmed by the owner. Repository verified PUBLIC.

## Problem and safety goal
Stage 50 introduced a transaction-consistent six-class configuration export; Stage 51 authenticated the native file contents with server HMAC and explicitly marked unsigned historical sources. Neither establishes that the settings presently held by the LIS still match a previously exported record. Before any future clinical/financial approval decisions, reviewers need to identify drift without treating a signed historical export as live truth or leaking off-branch prices and clinical values.

## Stage 52 implementation
- New `GET /api/catalog/imports/[id]/bundle-drift?after=N` compares staged source values against live counterparts using exactly the same six native export projections: TEST, COMPONENT, UNIT, REFERENCE_INTERVAL, PRICE_LIST, PRICE_LIST_ITEM.
- Every request starts with the tenant organization lock inside a **REPEATABLE READ** transaction, reads current user role and session permissions (intersection only), current branch and department grants (intersection only), and independently enforces clinical reference-range and pricing privileges when those classes are present. Batch must belong to the current organization and **original author**, still be native `CONFIG_BUNDLE_REVIEW` in `DRAFT` status with a source checksum, and contain at most 5,000 unprocessed `WARNING` rows. Off-branch, foreign-tenant, missing/reassigned or inaccessible master and *source parent* identities fail closed for the **entire batch before showing any page**.
- A full source-vs-current object comparison preserves exact serialized Decimal strings (no floating point approximation), timestamps, method/branch/component links, normal/critical values, and source price-list/branch relationships. Pure field-diff helper returns `UNCHANGED` or `DRIFTED`, bounded changed **field names** and an overflow indicator; it never returns old/current clinical or financial values. It is read-only on catalog, clinical, patient, invoice, result and financial masters.
- Displays a **100-row cursor-paged Arabic/English comparison** in the existing signed-bundle review screen. Clear warnings distinguish Stage 51 verified source status from unsigned historical source, and state that comparing a signed export **is not approval or activation**.
- An audit event logs reader, organization, branch, batch, page cursor, count, number changed and source attestation status without leaking raw content. No schema migration, approval token, configuration restore or active value update.

## Automated acceptance evidence
- `tests/stage-52-catalog-bundle-drift.test.ts` covers exact monetary/clinical decimals, nested fields, omitted/extra values, bounded safe field-path reporting, six-class and whole-batch scope rules, live role/branch/department checks, explicit unchanged/changed classification, and no master mutation.
- `tests/stage-52-catalog-bundle-drift-mariadb.integration.test.ts` uses **two independent MariaDB sessions** to prove revoked live branch grants are visible after the tenant lock is released; reauthorization must be explicit; source clinical and financial reads remain consistent across intervening committed writes, while later reads show drift. Client-private and foreign-tenant records are excluded.
- New MariaDB acceptance test is wired into CI alongside all previous suites. Complete Prisma migration/status/generate, safety tests, TypeScript, lint, bilingual UI/theme checks and Next.js build are mandatory for feature SHA and independently for merged main.

## Non-goals and preserved master scope
- This is a bounded **read-only difference preview**, not automatic merge, backup restoration, approval, pricing activation, clinical reference range approval, a critical-limit override, or authorized medical sign-off.
- Stage 51 HMAC is verified when the original file is staged. The batch summary carries verification evidence; this endpoint does not falsely claim to reverify a signature from the subset of staged rows. A verified source can be stale; **every** review rechecks live permissions and records.
- Unrelated writers not coordinating on the organization lock can still commit while a comparison is performed; repeatable-read protects against mixing data from different commits after the transaction's consistent-read snapshot.
- Future governed authorization, conflict resolution, key rotation and large-bundle snapshots remain within scope. Do not silently overwrite approved historical reference intervals, released results, posted invoices or prices.
- No legacy stages are reopened, no approved features removed. All **88 sections of 02_MASTER_SCOPE.md** remain binding. Analyzer Bridge PR #128 stays Draft/unmerged. Full manual, hardware/physical analyzer, scanner, clinical and financial end-to-end UAT, security provider verification and disaster-recovery restore test remain **DEFERRED** until full implementation; passing CI is not clinical go-live acceptance.
