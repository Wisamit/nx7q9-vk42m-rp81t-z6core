# Stage 60 — Independent, Domain-Separated Review of Unapproved Policy Drafts

## Purpose
Stage 59 records seven proposed clinical/financial signatory-policy topics in an append-only **UNAPPROVED_DRAFT** Audit ledger. The original author could record versions, but an independent clinical or financial procedural reviewer could not yet document objections. Stage 60 introduces **two distinct, independent procedural reviews** without creating legal/medical/finance signing powers or publishing any master value.

## Implementation
- `src/lib/catalog-policy-draft-review.ts`: allowlisted procedural domains (`CLINICAL`, `FINANCIAL`), dispositions (`NOTED_FOR_DISCUSSION`, `RETURN_FOR_REVISION`) and fixed coded objections. Clinical-only reasons cannot be used in financial review and vice versa; `NOTED_FOR_DISCUSSION` requires a specific discussion-only reason, never an `APPROVED` value. Immutable decision evidence binds **draft AuditEvent ID, policy revision, digest and domain**. Any approval/activation flag true fails validation.
- Independent reviewer **GET and POST** at `/api/catalog/imports/[id]/policy-review`. GET requires exactly `draftEventId` and `domain` and returns only the latest valid draft's seven policy-choice codes to a live-authorized independent domain reviewer. POST allows **exactly** `draftEventId,domain,disposition,reasonCode` in a <=1KiB JSON payload, validates everything server-side, serializes via active organization's `FOR UPDATE` row and `RepeatableRead`, and rechecks live user, role and tenant/active-branch and department intersections with the original session. It requires `catalog.manage` + `catalog.reference_ranges.manage` for clinical, or `catalog.manage` + `pricing.manage` for finance. The batch must be a live `CONFIG_BUNDLE_REVIEW` draft in the same organization. Author == reviewer is forbidden. The review must reference the **latest immutable policy draft** written by the batch author and bound to the active branch, source checksum, and complete digest; older revisions fail closed (409).
- At most one procedural decision per domain per revision. Duplicate identical action by the same reviewer is idempotent; contradictory/replaced decision fails 409. The same human cannot review both clinical and financial domains for a revision, and neither may be its author. The two domains can be reviewed independently by different users. Other reviewers cannot overwrite a recorded domain decision. Changes to the Stage 59 draft create a new AuditEvent ID and invalidate previous review eligibility; historical decisions remain immutable.
- `GET /api/catalog/imports/policy-review-queue` returns only a bounded, newest-version list of eligible active-branch draft IDs, revision numbers, and eligible domains, **never names, full source JSON, patient data, clinical limits or financial prices**. It revalidates present role/branch/department grants inside the same tenant transaction. Access to actual choices requires additional exact-event domain-authorization on GET detail.
- Bilingual `CatalogPolicyDraftReviewQueue` on existing `/catalog/expert-reviews` alongside Stage 54 drift findings. Reviewers must explicitly inspect latest draft, then select a domain-specific coded objection or log "noted for discussion" (expressly **NOT approval**). After the append-only audit outcome, UI refreshes the queue. Each POST revalidates independently to prevent stale/preflight authorization bypass.
- No new migration, production master update, user-role elevation, clinical approval, price-list activation, final e-signature, or historical report amendment.
